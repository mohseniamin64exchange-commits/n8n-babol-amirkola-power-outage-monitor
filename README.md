# سامانه پایش خاموشی برق بابل و امیرکلا

پروژه n8n برای دریافت برنامه خاموشی، استخراج اطلاعات فیدرهای موردنظر و ارسال پیام در تلگرام.

## وضعیت فعلی

- منبع بابل: سایت «بابلی‌ها»
- فیدر بابل `097`: شهرک صالحین و گلستان ۱۵
- فیدر بابل `169`: فولادکلای بابل‌کنار
- فولادکلای دیگری با فیدر `407` نیز در داده‌های سایت دیده شده است؛ این پروژه عمداً آن را انتخاب نمی‌کند.
- منبع امیرکلا: کانال ایتا
- خروجی: پیام تلگرام
- زمان‌بندی n8n سالم بوده؛ خطاهای مشاهده‌شده بیشتر مربوط به DNS و دسترسی Docker به ایتا/تلگرام بوده‌اند.

## اصلاح مهم کد بابل

نسخه نهایی در [`code/babol-feeders-097-169.js`](code/babol-feeders-097-169.js) قرار دارد. این کد:

- هر کارت خاموشی را جداگانه بررسی می‌کند.
- شماره فیدر را فقط از ابتدای آدرس کارت استخراج می‌کند.
- ساعت را فقط از ویژگی‌های `data-start` و `data-end` همان کارت می‌گیرد.
- اعداد داخل آدرس، شماره کوچه و گلستان را ساعت تشخیص نمی‌دهد.
- فقط فیدرهای `097` و `169` را وارد پیام می‌کند.

در نود Telegram، مقدار `Text` باید در حالت Expression باشد:

```javascript
{{ $json.message }}
```

## رفتار هنگام خطا

برای اینکه خطای منبع امیرکلا مانع اجرای شاخه بابل نشود، در نود دریافت کانال امیرکلا:

```text
Settings → On Error → Continue (using error output)
```

همین سیاست را می‌توان برای نود HTTP بابل نیز اعمال کرد تا خرابی موقت یک منبع کل Workflow را متوقف نکند.

## خطاهای شناخته‌شده

### DNS ایتا

خطای `The DNS server returned an error` یعنی کانتینر Docker نتوانسته دامنه ایتا را Resolve کند. VPN افزونه مرورگر روی Docker اثر ندارد؛ در صورت نیاز باید VPN سراسری ویندوز یا Proxy سازگار با Docker تنظیم شود.

### اتصال تلگرام

خطای `The service refused the connection` معمولاً یعنی Docker به `api.telegram.org` دسترسی ندارد. پس از فعال‌کردن VPN سراسری، Docker Desktop را بسته و دوباره اجرا کنید و سپس کل Workflow را آزمایش کنید.

### اجرای خطاداده‌شده

وصل‌کردن VPN، اجرای قبلی را خودکار تکرار نمی‌کند. اجرای بعدی Schedule از ابتدا انجام می‌شود. اگر نود حذف تکراری‌ها داده را در اجرای ناموفق ثبت کرده باشد، ممکن است لازم شود تاریخچه Deduplication یک بار پاک شود.

## بازیابی بعد از نصب مجدد ویندوز

1. Git، Docker Desktop و n8n را نصب کنید.
2. این مخزن را Clone کنید:

```bash
git clone https://github.com/mohseniamin64exchange-commits/n8n-babol-amirkola-power-outage-monitor.git
```

3. فایل موجود در پوشه `workflows` را در n8n Import کنید.
4. Credential تلگرام و سایر رمزها را دوباره داخل n8n بسازید.
5. اتصال Docker به سایت بابل، ایتا و تلگرام را تست کنید.
6. Workflow را ابتدا دستی اجرا کنید و پس از تأیید، حالت Active/Published را روشن کنید.

## اطلاعات محرمانه

توکن واقعی تلگرام، Chat ID خصوصی، رمزها و Cookieها نباید Commit شوند. فایل `.env` در `.gitignore` قرار دارد و فقط قالب `.env.example` ذخیره شده است.
